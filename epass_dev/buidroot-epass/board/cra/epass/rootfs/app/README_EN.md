# CRA Electric Pass Extension Application Directory

Read this in other languages: [English](README_EN.md), [中文](README.md).

After Buildroot merges the rootfs overlay, this directory appears on the device as:

```text
/app/
```

It stores third-party extension applications installed in the device's internal NAND.

## Directory Provenance

| File | Origin | Description |
| --- | --- | --- |
| `.gitkeep` | Unchanged from upstream | Keeps the otherwise empty `/app` directory in Git |
| `README.md` | Added by CRA | Current Chinese documentation |
| `README_EN.md` | Added by CRA | English documentation |

The upstream rootfs overlay does not ship any third-party applications. Application directories later placed in `/app/` by users are runtime or distribution content. They are not generated by Buildroot and must not be treated as trusted upstream software merely because they are stored here.

The CRA Electric Pass main program is installed by its Buildroot package at:

```text
/root/epass_drm_app
```

The main program and `/app` extensions therefore belong to separate layers. Do not copy the current main project into `/app` or convert it into a third-party application.

## Scan Locations

At startup, the main program scans two application locations:

```text
/app/       Applications in internal NAND
/sd/app/    Applications on the SD card
```

The corresponding source configuration is:

```c
#define APPS_MAX 64
#define APPS_CONFIG_VERSION 1
#define APPS_CONFIG_FILENAME "appconfig.json"
#define APPS_PARSE_LOG "/root/apps.log"
#define APPS_DIR "/app/"
#define APPS_DIR_SD "/sd/app/"
```

Applications from internal NAND and the SD card are added to the same application list, which can currently hold up to 64 valid entries.

## Application Directory Structure

The application scanner only checks subdirectories under `/app`. A standalone executable placed directly in the `/app` root is not recognized as an application.

A basic application layout is:

```text
/app/
└── example_app/
    ├── appconfig.json
    ├── example_app
    ├── icon.png
    └── other application resources
```

In this structure:

- `appconfig.json` contains application metadata and launch settings;
- `example_app` is an ARM Linux executable that can run on the device;
- `icon.png` is an optional application icon;
- any other resources are read and managed by the application itself.

The executable must target the current ARM926T EABI soft-float Linux environment. Windows EXE files, x86 or x86-64 desktop programs, and ARM programs built for an incompatible ABI cannot run on the device.

## `appconfig.json`

The application configuration filename is fixed:

```text
appconfig.json
```

The current configuration format version is `1`. A complete example follows:

```json
{
  "version": 1,
  "name": "Example App",
  "uuid": "12345678-1234-1234-1234-123456789abc",
  "executable": {
    "file": "example_app"
  },
  "type": "fg",
  "screens": [
    "360x640"
  ],
  "description": "Example application",
  "icon": "icon.png",
  "extensions": [
    ".txt"
  ]
}
```

### Field Definitions

| Field | Required | Description |
| --- | --- | --- |
| `version` | Yes | Configuration format version; currently must be `1` |
| `name` | No | Display name; the application directory name is used when this field is missing or empty |
| `uuid` | Yes | Unique application identifier; must be a valid, parseable UUID |
| `executable` | Yes | Executable file within the application directory |
| `type` | Yes | Application launch type |
| `screens` | Yes | List of display resolutions supported by the application |
| `description` | No | Application description; defaults to `无描述` (“No description”) when omitted |
| `icon` | No | Icon path relative to the application directory |
| `extensions` | No | File extensions handled by the application |

The recommended `executable` form is an object:

```json
"executable": {
  "file": "example_app"
}
```

The parser also accepts the legacy simplified form:

```json
"executable": "example_app"
```

## Application Types

`type` accepts the following values:

| Value | Type | Launch Behavior |
| --- | --- | --- |
| `fg` | Regular foreground application | Can be launched directly from the application list and can also handle associated files |
| `bg` | Background application | Can be started or stopped while the main interface remains active |
| `fg_ext` | File-associated foreground application | Cannot be launched directly from the application list and is invoked only through an associated file |

### Foreground Applications

When launching a foreground application, the main program generates:

```text
/tmp/appstart
```

This temporary shell script:

1. Grants executable permission to the application.
2. Changes to the application directory.
3. Starts the corresponding executable.
4. Passes the full file path when launched through a file association.

The main program then exits its current UI, allowing the system startup flow to execute the temporary script. After the application exits, the system can restart the CRA Electric Pass interface.

### Background Applications

A background application runs in its own process group. The main program records its PID and can:

1. Send `SIGTERM` to request a normal shutdown.
2. Wait for the configured timeout.
3. Send `SIGKILL` if the process still has not exited.

If a background application is already running, the main program does not start a second instance.

## Display Compatibility

The current main program uses:

```text
360x640
```

The application's `screens` array must therefore contain at least:

```json
"screens": [
  "360x640"
]
```

The parser also recognizes:

```text
480x854
720x1280
```

However, only a resolution enabled when the main program was compiled is considered compatible with the current firmware. If no entry matches, the application is not added to the application list.

## Icons

`icon` is a path relative to the application directory, for example:

```json
"icon": "icon.png"
```

The main program checks whether the icon exists and is readable. If `icon` is omitted, its path is invalid, or the file is unreadable, the program uses:

```text
/root/res/defaulticon.png
```

## File-Extension Associations

`extensions` declares the file types handled by the application:

```json
"extensions": [
  ".txt",
  ".json"
]
```

Each extension should include its leading dot. When the file manager opens a matching file, it passes the file's full path to the application as a single command-line argument.

The extension map can hold up to 128 entries. If several applications register the same extension, review the current mapping implementation and actual load order to avoid an ambiguous handler.

## Load-Time Validation

When loading an application, the main program checks:

1. Whether the application subdirectory is accessible.
2. Whether `appconfig.json` exists and is readable.
3. Whether the JSON can be parsed.
4. Whether `version` equals `1`.
5. Whether `uuid` exists and has a valid format.
6. Whether the executable field exists.
7. Whether the executable exists and is readable.
8. Whether its permissions can be changed to `0755`.
9. Whether `type` is valid.
10. Whether `screens` exists and is compatible with the current firmware.
11. Whether the icon and extension information is valid.

An application that fails validation is not added to the application list. Parsing information is written to:

```text
/root/apps.log
```

## Access from a Computer

The device's uMTP Responder configuration exposes `/app` as writable storage:

```text
storage "/app" "app" "rw"
```

When the device enters MTP mode, the computer displays a storage entry named `app`. It can be used to copy, update, or remove extension application directories.

After an MTP transfer, make the main program rescan the application list or restart it so that it does not continue using stale parsing results.

## Security Boundary

The current application loader validates the configuration format and file readability, but it does not verify:

- application digital signatures;
- SHA-256 checksums;
- publisher identity;
- program provenance;
- system interfaces accessed by the application;
- whether the application contains dangerous or destructive behavior.

After a successful load, the main program grants the executable `0755` permissions and starts it. Therefore:

- Do not install binaries from unknown sources.
- Do not copy Windows or desktop Linux programs directly into this directory.
- Do not run third-party programs before verifying which hardware resources they can access.
- Back up application data and device resources before updating an application.
- Each application package should record its source code, build environment, target architecture, version, and checksum.
- Do not move the CRA Electric Pass main program itself into this directory.
